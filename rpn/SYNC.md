# rpn/ — RPN V0 ฉบับออนไลน์ · คู่มือรับเวอร์ชันใหม่จากส่วนกลาง

> อัปเดตล่าสุด 2026-10-14 · เวอร์ชัน RPN ที่ฝังอยู่ตอนนี้: **V0.9.5** (`rpn/VERSION`)

**RPN V0** คือโปรแกรมวางแผนที่ส่วนกลางพัฒนาต่อจากหน้า admin เดิมของเรา ต้นฉบับรันในเครื่องและเก็บข้อมูลใน IndexedDB
เรายกมาทั้งชุดไว้ในโฟลเดอร์นี้ แล้วต่อเข้ากับ Firestore จริง (`route-plan-71e2e`) ใช้เป็นแท็บ **วางแผนคิวงาน** และ **ภาพรวมแผน**
ใน `index.html` โดยฝังเป็น iframe `rpn/RoutePlannerV0.html?embed=1&center=…` (ดู `RpnHost` ใน `index.html`)

**หลักสำคัญ:** เราไม่แก้ไฟล์ของ RPN เลย งานต่อเชื่อมทั้งหมดอยู่ใน **2 ไฟล์ของเรา** (`rpn-online-pre.js`, `rpn-online.js`)
และในไฟล์ของระบบเราที่อยู่นอก `rpn/` เวอร์ชันใหม่จากส่วนกลางจึงวางทับได้ด้วยสคริปต์เดียว แล้วไล่เช็คตามรายการด้านล่าง

## 1. ขั้นตอนรับเวอร์ชันใหม่ (ทำตามลำดับ)

1. **สร้าง branch ใหม่** จาก `staging2` เช่น `rpn-v0.9.6`
2. **ซิงก์ไฟล์:**
   ```bash
   node tools/sync-rpn.mjs "C:\Users\...\Desktop\RPN V0 Pre-Launch"
   ```
   - สคริปต์ลบทุกไฟล์ใน `rpn/` ยกเว้นไฟล์ของเรา 3 ไฟล์ (หัวข้อ 3) คัดลอกชุดใหม่มา แล้วแก้ `RoutePlannerV0.html` ให้เป็นออนไลน์ (หัวข้อ 2)
   - ถ้าสคริปต์หยุดพร้อมข้อความ "หาจุดแก้ไม่เจอ" แปลว่าส่วนกลางเปลี่ยนโครง HTML ให้แก้ regex ใน `tools/sync-rpn.mjs`
3. **ดูว่าส่วนกลางเปลี่ยนอะไร:** อ่าน `rpn/CHANGELOG.md` ใหม่ และดู `git diff --stat rpn/`
4. **เช็คจุดที่เราเกาะ (หัวข้อ 4):** ค้นชื่อฟังก์ชันและ id ในตารางกับไฟล์ใหม่ ถ้าหายหรือเปลี่ยนชื่อ ให้แก้ใน `rpn-online.js`
5. **เช็ค patch ที่เราอุดบัคของ RPN ไว้ (หัวข้อ 5):** ถ้าส่วนกลางแก้บัคนั้นแล้ว ให้ลบ patch ของเราออก
6. **เช็คสัญญาข้อมูล (หัวข้อ 7):** ถ้า RPN เปลี่ยนรูปข้อมูลร้าน (field ใหม่หรือเปลี่ยนชื่อ) ต้องตามแก้ฝั่งแอปเซลด้วย
7. **ทดสอบตามเช็คลิสต์ (หัวข้อ 8)** บนเครื่องตัวเอง ใช้ศูนย์ `TEST_…` สำหรับอะไรที่เขียนข้อมูล
8. **Deploy:** push `staging2` ก่อน รอ deployment "Production – sales-app-7ids" ขึ้น success แล้วค่อย push `staging` และ sync `main`
   (ห้าม push SHA เดียวกันเข้า `staging` กับ `staging2` พร้อมกัน — ดู CLAUDE.md หัวข้อ Branch/deploy map)
9. **หลัง deploy:** เปิดแท็บวางแผนของศูนย์จริง แล้วสลับไปทุกเดือนที่เซลใช้อยู่ (เช่น เดือนนี้ถึงอีก 2 เดือน) เพื่อให้ rpnCal ถูกคำนวณใหม่ด้วยโค้ดเวอร์ชันใหม่ (หัวข้อ 6)
10. **อัปเดตไฟล์นี้:** เลขเวอร์ชันด้านบน และเพิ่มบรรทัดในหัวข้อ 9

## 3. ไฟล์ของเราใน `rpn/` (ซิงก์แล้วไม่ถูกทับ)

### `rpn-online-pre.js` — โหลดหลัง `../auth.js` ก่อน `app-config.js`
- เปิดได้เฉพาะ role `admin` / `supervisor` คนอื่นเด้งกลับหน้าหลัก (redirect ที่หน้าต่างบนสุด เพราะอยู่ใน iframe)

|---|---|---|
| 1 | `LocalExtras` ตัวแทน (`distCode`, `backup` ว่าง) | โมดูลอื่นของ RPN ยังเรียก แต่เราตัด `local-extras.js` ออก |
| 2 | เตือนตอนนำเข้าไฟล์ที่รหัสศูนย์ไม่ตรงกับ `?center=` | กันนำเข้าไฟล์ผิดศูนย์ทับข้อมูลจริง |

| 7 | `RPNBridge.applyReorder` — อนุมัติคำขอจัดลำดับตลาดจากแอปเซล | ดู CLAUDE.md หัวข้อ market reorder |
| 7b | `RPNBridge.dayOffPreview` / `applyDayOff` / `restoreDayOff` + ครอบ `App.createPlan` (`wireCopy`) — เซลหยุด 1 วัน แบ่งร้านของวันนั้นไปวันทำงานก่อนหน้า/ถัดไปของสายเดียวกัน (หน้า admin เมนู "📆 เซลหยุด / แบ่งร้าน" = `DayOffUI` ใน `../index.html`) | `HolidayException` เดิมใน RPN ใช้ได้แค่โหมด weekday ทั้งศูนย์ ไม่มีปุ่มเปิด และไม่ย้ายร้านจริง (DMS ไม่เปลี่ยน) — อันนี้ย้าย `days`/`seqs` ในแผนจริง |
| 8 | ชื่อตลาด "สูตรเดิม" ในหน้าแนะนำชื่อตลาดของ RPN | ผู้ใช้ขอให้เลือกสูตรเดิมของเราได้ทั้งรายวันและทั้งสาย |

`RPNBridge` (หน้า admin เรียกผ่าน iframe): `dirty`, `go`, `reload`, `ready`, `applyReorder`, `dayOffPreview`, `applyDayOff`, `restoreDayOff`, `reconcileCal`, `legacyName`

## 6. rpnCal — วันที่จริงที่แอปเซลใช้ (สัญญาระหว่าง RPN กับแอปเซล)

RPN คำนวณวันเข้าเยี่ยมซับซ้อน (F1/F2 รายตลาด, รอบ ≤14 วันวิ่งซ้ำ +14 วัน, ช่องที่แยก ✂️ ซึ่งเลข Day เกินความยาวรอบ, End date)
แอปเซลจึง **ไม่คำนวณเอง** — §5 ใช้ `Runs.datesOf` (ตัวเดียวกับที่ส่งออก DMS) แล้วเก็บไว้ที่

```
plans/{ym}/routes/{สาย}.rpnCal = { v:1, ym, sig, cfg, days: { 'Day 3': { d:['2026-10-03','2026-10-17'], m:'ชื่อตลาด' } }, at }
plans/{ym}.rpnCalIndex        = { สาย: hash }
```

- **เขียนเมื่อไหร่:** ทุกครั้งที่บันทึกสาย (เดือนที่เปิดอยู่) + ตรวจทุก 4 วินาที เขียนเฉพาะสายที่ค่าเปลี่ยน · **คำนวณเฉพาะเดือนที่ RPN เปิดอยู่**
- **`sig`** = hash ของ (รหัสร้าน + days) ของร้านที่ไม่ `inactive`
- **`cfg`** = hash ของปฏิทินที่ใช้คำนวณ (override ของสาย ถ้าไม่มีใช้ `calendarConfig` ของเดือน) — เพิ่ม 2026-10-09
- แอปเซล (`RpnCompat` ใน `sales-app.js`) ใช้ rpnCal **เฉพาะเมื่อทั้ง `sig` และ `cfg` ตรง** ไม่งั้นใช้ `CalendarCtrl` เดิมคำนวณจากปฏิทินแทน
  (เช่น แก้ปฏิทินเดือนอื่นที่ RPN ไม่ได้เปิดอยู่ แอปเซลเปลี่ยนตามทันที แล้วกลับมาใช้ rpnCal เมื่อเปิดเดือนนั้นใน RPN)
- ก่อนเขียน §5 อ่านเอกสารสายจาก server เทียบ `sig` ก่อนเสมอ (กันเขียนวันที่ของเดือนเก่าที่ค้างในหน่วยความจำระหว่างสลับเดือน)
- **ฟังก์ชันที่ต้องเหมือนกันทุกตัวอักษร:**
  - `hash()` / `sig()` — `rpn-online.js` §5, `RpnCompat.hash/sig` ใน `sales-app.js`, `App._rpnSig` ใน `admin-data.js`
  - `cfgSig()` + รายการ `CFG_KEYS` — `rpn-online.js` §5 และ `RpnCompat.cfgSig/_CFG_KEYS` ใน `sales-app.js`
  - ถ้าส่วนกลางเพิ่ม field ใหม่ในปฏิทิน (เช่น โหมดใหม่) ต้องเพิ่มใน `CFG_KEYS` **ทั้งสองไฟล์** แล้วเปิดทุกเดือนใน RPN ใหม่ให้ rpnCal ถูกเขียนใหม่

## 7. สิ่งที่เราเพิ่ม/แก้ **นอก** `rpn/` เพื่อให้ระบบเดิมใช้ข้อมูลของ RPN ได้

### ข้อมูลของ RPN ที่ระบบเราต้องรู้จัก
- **สายเทียม `รอจัดสาย`** ใน `routeList` — ทุกที่ที่ไล่รายชื่อสายต้องข้าม: `users.js` (สร้าง user), `tasks.js`, `center-select.html` (นับสาย),
  `admin-cellsplit.js`, `admin-ui.js` (ภาพรวมทุกสาย), `admin-data.js` (`getRouteConfirmStatus`), `sales-app.js` (`RpnCompat.cleanRouteList`)
- **ร้าน `inactive`** (ออกจากแผน) — แอปเซลซ่อนด้วย `RpnCompat.clean()` และทุกจุดที่เขียน `stores` กลับต้องห่อ `RpnCompat.restore()` ไม่งั้นร้านที่ซ่อนหาย
- **field ร้านใหม่:** `inactive`, `wasPlan`, `runOf`, `fqs`, `fqRun`, `cys`, `vd` · center doc: `cyPoints`, `routeBase`, `masterKm`, `maxCycleCode`, `routeDist`
- **ร้านหนึ่งอยู่ได้หลาย Day** (F2/F4) — `approveMoveRequest` แทนเฉพาะ `fromDay` และย้ายค่ารายวัน (`cys`, `fqs`, `fqRun`, `vd`, `runOf`) ตามร้านข้างเคียงใน Day ปลายทาง

## 8. เช็คลิสต์ทดสอบหลังรับเวอร์ชันใหม่

- [ ] `index.html?center=402` → แท็บวางแผนคิวงานโหลดได้ ไม่มี error ใน console · แท็บภาพรวมแผนขึ้น · เมนูข้างเรียงตามหัวข้อ 7 (เมนูย่อยใต้วางแผนคิวงานเปิดหน้าต่างได้ครบ 4 อัน, ป้ายแดงซ่อนเมื่อเป็น 0)
